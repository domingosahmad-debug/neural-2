# Project Goldfish — selective independent review

Tony authorizes using this skill when the task warrants it, without asking him to name it. This is a small adaptation, not the upstream full swarm. Keep the capable main agent, current provider choices, source quality, required QA and human artistic acceptance. It grants no permission to resume paused work or change a production model policy.

## Choose the useful checkpoint

Use before consequential architecture/integration, an ambiguous multi-part app build, a costly edit assembly, or another broad rebuild after human rejection. For new substantial video work, review the source/song/story plan before building and one representative rendered passage before scaling. Reuse a genuine independent review already covering that exact scope instead of duplicating it. If an ambiguity is trivial or a clear fix is cheaper to verify directly, skip extra inference.

Read only the applicable lens: [software](references/software.md) or [video](references/video.md). The full upstream stages, repeated clean-round tests, documentation bootstrap and style reviewers are not defaults.

## Prepare evidence and dispatch

Keep the owner's normal conversation. Write a bounded review target in the project's existing state/artifact location. Identify project/revision, objective, relevant user constraints, protected work, intended behavior, exact plan/proof version and acceptance checks. Select the decisive code/ledgers/stills and record identities/provenance. Do not copy the owner's deliberation, private reasoning, earlier verdict or expected answers. Give the reviewer the facts needed to challenge the proposal.

Start ONE fresh read-only reviewer using native delegation; this user authorization covers that bounded delegation. Use the existing capable model by default; use a cheaper model only for a genuinely simple factual/comprehension check. Do not use the routine Explore agent for hard architectural or artistic judgment. No automatic provider switch, reserve bypass or paid service.

- Codex: use a general-purpose child with `fork_turns: "none"` or the actual equivalent fresh-context parameter. Supply the [reviewer contract](references/reviewer.md) and selected files. Tools/permissions remain host-dependent; prohibit mutations and unrelated history reads explicitly.
- Claude Code: prefer the installed `goldfish-reviewer` read-only custom Agent; start a new instance, not a fork/resume of the owner's conversation. Supply the review target, lens and constraints explicitly. Agent tools are Read/Grep/Glob, model inherit, medium effort, no persistent memory, `omitClaudeMd: true` where supported. Verify actual host support rather than asserting isolation from frontmatter alone.
- Claude Chat/Cowork: the imported skill is separate from Code's local configuration. Use a fresh native child only if that session actually exposes one; its tools/isolation must be checked there. Do not assume the local custom Agent is registered in that surface.
- Antigravity: use a fresh native `invoke_subagent` when actually exposed. If unavailable, do not simulate independent personas in the owner's chat or launch another provider secretly. Finish useful preparation/direct checks, mark independent review NOT RUN and retain the checkpoint for a capable host.
- Neural: use a real app-owned context_mode=fresh_review task with supplied evidence and completion events. Neural integration is activated under Tony's3November authorization; see NEURAL_STUDIO/shared/GOLDFISH_NEURAL_WORKFLOW_20261103.md for exact task fields. Preserve the one native writer and all durable director/ordinary-worker sessions. A persistent resumed Sol worker is independent of Claude but is not automatically a fresh Goldfish context.

For tool-less adapters deliver actual bounded text and explicit images, not paths alone. Missing/unsupported required evidence is a preflight failure, not zero findings. A fresh child can still inherit host instructions/filesystem access; disclose this limit, retain safety constraints and never claim perfect objectivity. See [provenance and host limits](references/provenance.md).

## Resolve within a useful budget

Default to one focused reviewer per needed checkpoint, without a synthesizer or team. Wait on the native completion event and end inference while work runs. A timeout/missing report is NOT RUN; reconcile it before a new attempt and never replay unknown execution.

The owner evaluates evidence-backed findings and applies ordinary authorized fixes. Do not ask Tony to approve every report or repeat decisions already settled. Escalate only a genuinely missing creative choice, input, authorization or capability. Request at most one targeted recheck of materially changed blocker/major findings at that checkpoint. A separately needed plan and rendered-proof review are different checkpoints. Additional review requires a concrete changed scope/new evidence; otherwise record the blocker and stop the review loop. Budget exhaustion never turns an unresolved defect into approval.

Store the actual report, scope/version, findings, resolution evidence, remaining gates and next action in existing project records. No scheduler or always-running reviewer. Record reported tokens/calls, time and useful defects caught when available; assess total rework on real tasks without benchmarks or invented savings. Never promise one/two-pass completion.
