## How Tony uses it

1. Click Lumen, then **Try Lumen as an editor**.
2. Choose a source project with original footage/music. Enter a concrete brief including duration, desired style and acceptance criteria. Press **Queue trial edit**.
3. Alternatively tell Relay, for example: "Tell Lumen to make a twenty second AMV edit." Relay uses the current production's source project. For a different source, use the source selector.
4. Lumen starts a NEW trial project. Existing edit projects and completed scenes are not overwritten or treated as raw source. It waits if another director, worker, native request, local job, completion chain or learning call owns the lane.
5. Its panel reports the actual task/model, state, waiting reason, turn count, memory path, prior trials and errors. A real registered full trial review gets **Open trial review** after the host decode/audio-presence gate passes.
6. Save specific trial feedback in **Teach it from this trial**. The next trial receives previous feedback and current workflow-scoped corrections. Improvement is judged from actual results, not a growing lesson count.

Lumen stays a worker, not a replacement director. The director can use `neural_lumen_editor` to assign/status/stop/reconcile/resume/release/record feedback. The native Claude/Gemini director instructions describe the equivalent authenticated API. A director-created trial registers its completion watch; that parent ends inference while waiting. Only its own exact delegation watch and current direction can hand off the production lane. Unrelated watches or a later production direction still block takeover.

## Tools, continuity and collective

- The installed official Antigravity CLI executes the configured exact Gemini Flash model with local file/shell tools in accept-edits mode. Official account/model metadata is checked once before each meaningful turn. There is no API-billing fallback or automatic model substitution. Other learner provider/model configurations remain available for learning but do not inherit an untested editing adapter.
- Lumen reads the same bundled station workflow, skills, source checks and TonyFX execution protocol as other workers. Deterministic media/native work uses the shared local engine; native work stays serialized with live project/state guards and no replay of UNKNOWN requests.
- Each trial keeps its provider conversation ID across its continuation turns. Cross-trial continuity uses durable files: `data/lumen-editor/<workflow>/trials/<id>/MEMORY.json`, `TRIAL.json`, `STATE.md`, `CHECKPOINT.json`, turn evidence and feedback. MEMORY freezes supplied lessons, skill hashes, source project and shared team context. New trials receive earlier trial/feedback pointers, not an unlimited transcript.
- Findings/help are attributed to Lumen in the shared collective. A known stopped blocked trial can hand a diagnosis back to its director. Unknown execution keeps the editing lease until actual reconciliation. It never invents a teammate response or opens a competing native editor.
- Learning and editing are separate roles. Reflection waits while Lumen owns a trial. Its local observer retains events for later learning, including sourced trial feedback. Completion is not automatically a new universal rule.

## Usage and limits

Reading status, queueing, local event observation and waiting do not start model turns. Active trial reasoning consumes the connected Gemini allowance. Owned local-job completion wakes one meaningful continuation; there is no model status-polling loop. Sixteen meaningful turns is the current bounded trial limit, followed by an attention notice/diagnosis rather than silent continued inference. This limit is not an estimated edit duration.

Saved skills and lessons are retrieved instructions. They do not retrain Gemini's weights, guarantee complete autonomy, or establish superiority over other models. The file/shell role is provider-managed and instruction-scoped, not a hard filesystem sandbox. It can construct a complete trial, but this integration does not give it audio listening or full-speed video perception. Decode, audio presence, alignment and numeric checks remain technical evidence; final motion/listening/artistic acceptance stays with Tony at the end of the review.

Stop preserves partial work. Known-safe stopped work is PAUSED; uncertain process/local/native execution is UNKNOWN. Reconcile uses actual stop/idle/completion evidence without replay. Explicit Resume continues the same trial; Release frees a reconciled paused lane. Never clear locks or fake stop evidence to bypass an UNKNOWN state.
