# Production checkpoints — authoritative current contract

The roadmap is a **revision-specific human requirements checklist**, separate from each local pipeline. It costs no model calls to read. Update it at meaningful decisions, not on a timer. Idle status/ETA refresh never starts inference.

1. Read `GET /api/production`, dynamic `neural_production` action `status`, or `python tools/production.py status`. On a new authorized edit/revision record 5–15 concrete checkpoints derived from the actual brief. Carry forward unresolved human requirements explicitly; a proof/render is not the entire task.
2. Update with `neural_production` action `update`, `POST /api/production/update`, or `python tools/production.py update PLAN.json`. Required fields: `project_id`, `revision`, `title`, `scope`, `expected_updated_at` (previous value; null for first plan), `steps`. All clients share the same persistent record. Old plans are archived. Only change it at actual decisions; do not call a model for bookkeeping.
3. Each step has `id`, `title`, `owner`, `gate` (`technical`, `sequence`, `picture`, `motion`, `listening`, `human`), `status` (`todo`, `working`, `built`, `verified`, `blocked`, `not_tested`, `awaiting_review`), and `note`. Verified requires `method` and `evidence` paths to compact studio files. Evidence fingerprints must still match. New revision requires a fresh scope/evidence decision; never copy old ticks as if rechecked.
4. Methods: technical=`numeric`/`native_readback`; sequence=`source_ledger`/`sampled_frames`/`playback`; picture=`sampled_frames`/`playback`; motion=`playback`; listening=`listening`; human=`human_acceptance`. State exactly who reviewed what and the limits. These are reported evidence claims, not automatic proof of perception. A director cannot set human acceptance with its tool. Never relabel sampled stills as motion/listening or infer approval from an idle leader.
5. Optional per-outstanding-step `estimate: {low_minutes:3, high_minutes:8, basis:"one transition proof + one playback"}` is a remaining-work planning range. Only supply supported estimates. Unknown/rework/blocked/listening without capability => no reliable ETA. Estimates expire after 15 minutes without a real checkpoint update. UI sums the sequential planning ranges; human response time excluded. Local operation timing ranges are separately labeled, use noncached measured history and abstain for variable workload/insufficient samples/overruns. No fixed fake eight-step bar or precise countdown.

## Quality and speed contract

- Before effects/build: one compact canonical source/sequence ledger with integer half-open timeline/source ranges, original media identity, quote speaker/whole phrase, setup → action → follow-through/payoff, explicit repeat reason if intentionally approved. Run shared `validate_plan`: timeline/source bounds, dialogue/caption collisions and **source-range reuse** must pass. Aliased source IDs for the same physical file do not hide repeated ranges. Native compiler uses the same gate. A hand-written repair still needs equivalent current-source evidence, including nested/occluded final visible owners; direct plan PASS cannot validate absent nested mappings.
- A human rejection must become a concrete failing checkpoint and a scoped repair acceptance test. “Remove early technique” means picture, voice, caption and setup/payoff ownership as applicable; deleting words alone does not remove a repeated ritual. Record exact failed ranges and what must be preserved. Keep good sections; prove the hardest revised boundary first, then one full review.
- Do not open a new full-model audit for work already measured. Independent bounded specialists can inspect disjoint evidence only when capable and worthwhile. No extraction/arithmetic/status watching by chat models. Use one deterministic chain and one final completion wake. No duplicate native editor or replay of UNKNOWN.
- Deliver a **review copy** with independent gates. Never count numeric peaks/decode/preservation as artistic sequencing, motion or listening. Required sound effects, complete spoken ownership, new text style and source reuse remain open until actually checked. If capability is missing disclose it once and keep the failed/not-tested requirement visible; do not render endless revisions pretending the gate passed.
- Human playback/listening belongs at the **end of production**. Finish all actionable construction, debugging and technical checks first. If the current adapter cannot perform a perceptual check, retain that explicit limitation, use `awaiting_review` for the separate final perceptual checkpoint, and supply `review_preview_id` for this project's registered full review of the same revision. The backend rejects this handoff while actual production tasks remain unfinished or the full review is missing. Split completed sound integration (technical, with real evidence) from final listening; never label the entire completed sound task blocked just because listening is pending. This state is not a PASS or approval. The human can review once, confirm the final checks explicitly, or give remarks for a scoped revision. No intermediate human continuation message is required.
- Current role routing is Sol/Codex → native Claude Opus subscription → final Gemini fallback after confirmed allowance refusal. Read `data/command/DIRECTOR_POLICY.json`, not historical Argon ordering. Never change providers or buy extra usage to update a board.
